The Rules
​
Use It When
The same expectations should apply broadly without being repeated in every prompt.
​
Example
Build and test commands, coding standards, architecture rules, and security requirements.
Custom Agents
A specialized agent with its own instructions, allowed tools, and isolated context.
​
The Specialist
​
Use It When
You want a dedicated specialist for a recurring job, with strict limits on what tools it can touch.
​
Example
A read-only security auditor, a pull request reviewer, a database specialist, or a codebase researcher.
Agent Skills
A folder of instructions, scripts, and templates that an agent loads on demand only when relevant to a task.
​
The Know How
​
Use It When
You have a repeatable workflow or playbook that should only load when needed.
​
Example
Diagnosing bugs, code review, refactor principles, migration scripts, product specific knowledge, or testing patterns.
MCP Servers
A standard way, using the Model Context Protocol (MCP), for AI agents to call external APIs, databases, and tools.
​
The Connection
​
Use It When
The agent needs live information or needs to take action outside your repository.
​
Example
Querying a live database, pulling errors from monitoring APIs, updating issue trackers, or driving a web browser.
Agent Hooks
Scripts or shell commands that automatically run at specific points in an agent's workflow.
​
The Determinism
​
Use It When
A check, formatter, or security rule must always run without relying on the AI to remember.
​
Example
Run a code formatter after every file edit, scan for secrets, or block an agent from disabling required tests.
Agent Plugins
Installable packages that bundle instructions, agents, skills, hooks, and MCP servers into one shareable unit.
​
The Package
​
Use It When
You want to version and share a context engineering setup so anyone can easily install it.
​
Example
A team onboarding plugin that installs your PR reviewer agent, deployment skills, and MCP servers in one command.

How Context Engineering Fixes It
​
​
Rediscovering the repo every session
The agent runs dozens of searches just to figure out your folders, build commands, and conventions.
​
​
​
Custom Instructions give the map up front
Always-on rules hand the agent your architecture, commands, and standards on turn one.
​
​
Stuffing every workflow into AGENTS.md
A giant instructions file gets paid for on every single turn, even when most of it is irrelevant.
​
​
​
Agent Skills load know-how on demand
Heavy playbooks, scripts, and templates stay out of the context window until the task needs them.
​
​
Prompting vague tasks and fixing bad diffs
The agent builds the wrong thing, and you burn rounds of follow-up prompts trying to patch it.
​
​
​
Specs catch mistakes before code is written
Planning first aligns on files, constraints, and edge cases while changes are still cheap.
​
​
Using the model for routine checks
Waking up an LLM to format files, check lint rules, or poll build status burns tokens for zero value.
​
​
​
Hooks and scripts run deterministically
Shell commands and hooks handle formatting, tests, and guardrails for zero tokens.

Nothing Has Changed About Software Engineering
Ben Eggers, a Software Engineer at OpenAI, argues that all the hard parts of building software are still here and still hard. AI Agents move that work, but they do not make it disappear.
The job of a Software Engineer now is to deliver code they have proven to be correct. That still requires technical humans in the loop to define intent, design systems and APIs, structure codebases, build tests and CI/CD, secure infrastructure, and review what AI produces.
You might not need to read the code anymore
But you really do need to read the context
